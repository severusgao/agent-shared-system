# 全体系复盘

本文件维护跨组件复盘流程。共享授权与进化门槛引用 [AGENT_RULES](../../../memories/AGENT_RULES.md#evolution-audit-gate)；记忆读写引用 [记忆触发规则](../../agent-shared-memories/references/TRIGGER_POLICY.md)。

## 证据与覆盖

按当前用户要求、已批准共享约定、可追溯对话与任务结果、实际维护对象的顺序核对。证据可以来自任何业务任务，但改进对象限定为 Agent Shared。业务数据、项目进度和知识文章不因此成为共享规则。

报告声明请求的周期与实际覆盖。缺失设备、无法访问或解析的来源、未结束任务分别列出。Mac 的报告不代表 Windows 全部工作。未知结果保持未知；重复分支、归档副本、工具结果及模型自己的建议不能算成多次独立用户纠正。

## 跨批次归纳

围绕现有主题页需要回答的固定问题整理证据，例如哪些条件下容易返工、某项共享决定是否仍适用。以原始事件、实际经历和验证材料关联依据；多个批次、归档副本、摘要转述或多个 Agent 重复同一建议不增加独立支持。不同事件也可能属于同一次事故，须核对对象、发生时间、来源与结果，再判断独立性。

把用户确认、实际观察、模型推断和正式决定分别表达；保留否定、条件、例外、理由、说话者与真实结果，并检查重要反例。允许有依据的归纳，优先增量修改现有偏好、决策或流程页；未获确认/采纳的分析留在本轮材料。具体收录与修订由 [WRITE_POLICY](../../agent-shared-memories/references/WRITE_POLICY.md) 维护。

需要查找已有结论、重复候选、来源与状态时，使用 [统一查询](../../agent-shared-memories/references/QUERY.md)。它只定位共享记忆和已经审阅的复盘，不扩大为业务经历库。检索到记录之后仍需补读其适用条件与具体证据。

## 原因判断

| 发现 | 优先处理 |
|---|---|
| 缺少稳定方法、规则有歧义或冲突 | 提议修改对应正式维护源 |
| 现有规则充分，但没有读取或遵循 | 检查发现、路由、加载、调用前提和实际执行；不重复堆规则 |
| 本机依赖、链接、端口或运行配置异常 | 本机修复建议；共享层只记录可复用规则 |
| 临时需求、来源不明、结果未验证 | 跳过或待复核 |

Agent 发起的候选须符合既有进化门槛：发生至少两次，或复发成本明确较高；稳定可复用；现有覆盖不足；能验证。用户直接要求的范围内更新按该请求评估，不强求先发生两次故障。优先重复纠正与返工，其次损坏的公共流程，再考虑上下文与成本收益。零项合格也是有效结果。

## 维护形式与审阅

先比较复用、扩展现有入口、局部修改、脚本化和跳过；独立新技能必须有独立触发与反复使用价值。按 SKILL 的对象表转交治理入口。调度、原生配置或外部系统动作单独列为建议，不在首版创建。

每项候选包含问题、证据引用、已有覆盖、原因分类、维护对象、准确文字或行为差异、跨环境影响、验证、回退及文件基线。新审阅包使用 schema_version 2，逐项填写 macOS、Windows、WSL、独立 Linux 的 platform_assessment：是否适用、具体影响、验证状态和验证方式。通用规则面向整个共享体系；平台专用修复可只作用于相应系统，其他系统写清“不适用”的依据。设计兼容、文件同步和实际执行分别判断，尚未实测的环境保留 unverified。历史 schema_version 1 只用于读取旧记录，不作为新提案格式。新提案填写 `proposal_revision` 和完整候选的 `proposal_digest`；批准、应用、验证、替代和撤回记录均绑定 `review_id`、`candidate_id`、版本与摘要。文字、条件、基线或对象变化后重新生成版本，旧批准不转移。既有 v1/v2 包没有版本字段时仍可读取，批准关联明确待核验。使用模板和 `validate-package` 检查结构，Agent 仍负责真实性与适用性判断。准确差异引用附件时，按 [EVIDENCE](EVIDENCE.md#差异附件) 登记并核验附件摘要。

默认一个审阅包最多五项，不强凑。涉及共享记忆的部分最多三项相关改动，并经过记忆技能的 Candidate Gate；其余候选保留为待复核。有关联的变更标明依赖与应用顺序。

检索 `.agents/evolution/` 既有决定。已拒绝候选没有新的独立证据时不重复提出；只是重复采集、改写旧摘要或模型重新建议不算新证据。以维护对象和实际变更识别同一候选，避免标题变化绕过去重。

## 旧待审包与历史记录

先用统一查询核对决定记录及应用回执，再判断是否仍待审。原包中的 `proposed` 是提案快照，不覆盖后续批准、应用或验证。已实施的历史包保留原样；提案前基线与实施后文件不同是正常现象，不因此重建历史或补造旧批准。

尚未实施的候选若格式、附件或文件基线不再符合当前要求，停止续用，在决定记录中追加 `superseded` 及替代引用，保留旧包。按当前规则和最终源文件重新准备准确差异、基线、验证与摘要；不只替换旧基线后继续执行。旧包没有版本字段时，新包使用新 `review_id` 和版本 1，引用旧包但不补造其版本；已有版本的候选按版本递增。新版本仍须有覆盖它的真实批准。

旧记录没有版本绑定时，查询保留 `version_unknown`；明确的历史 `superseded` 标记说明旧包已经退出待审队列，不推定旧批准有效。替代仅表示不再续用旧提案，不代表新提案获批或已经应用。

## 记录与复核

用户要求复盘可授权生成并保存本轮脱敏报告和待审包；正式 Skills、Memories、MCP、脚本或接入状态的更新需获得相应批准。先报告准确差异和跨系统影响，再按批准范围一次应用；保存待审材料不产生正式修改授权。

每轮一个目录，保存覆盖说明、脱敏证据、审阅包与必要的验证材料；根部 `decisions.jsonl` 只保存候选标识、决定、证据标识、依据和状态变化。完整聊天、工具原始输出、数据库、暂存和备份保留在本机。

周期报告完成、证据核对和脱敏复核通过后，使用 `commit-review` 推进本机各来源游标；缺失或部分解析的来源不推进。复盘完成与候选获批、应用分开记录。跨设备导入摘要具有自己的来源标识，不改变原设备的采集游标。

批准、已应用、已验证和后续有效分别记录。无候选的普通任务保持安静；用户明确调用的周期复盘应说明覆盖与零项合格结果。

下次复盘分别检查机制正确性、Agent 判断与使用、维护成本。对实际发生的代表任务记录使用的现行条目/版本、关键适用条件、环境与 Agent、真实结果/验证引用、是否误用旧决定及额外步骤或返工；常规任务不强制逐次留日志。检查原问题是否重现、重复提醒是否减少、是否遗漏条件或错误触发。文本/临时材料测试只证明机制，新会话只证明该场景；没有后续任务时持续效果写为待验证。
