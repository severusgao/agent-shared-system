# 应用与恢复

先核对 [授权规则](../../../memories/AGENT_RULES.md#approval-required) 和本次真实批准范围。复盘先提交准确差异、跨系统影响、验证和临时副本清理方式；正式共享更新在用户批准后执行。保存脱敏报告和待审包不产生正式修改授权。批准范围内的必要步骤连续有效，不逐文件重复审批。

## 应用顺序

1. 用默认严格模式校验新审阅包、差异附件及跨系统评估，并传入 `--root` 核对实际共享目标；附件约定见 [EVIDENCE](EVIDENCE.md#差异附件)。交给对应治理入口检查已有覆盖、上游关系和依赖。选择能完成本批约定验证的一个环境应用；列明本批必须验证的项目和其他环境待验项目。
2. 核对批准对应的 review_id、candidate_id、proposal_revision 与 proposal_digest；旧版批准不转移。重读全部目标并核对批准时的 baseline；检查同步冲突。发生变化时停止重新提案，不静默合并。历史包用于追溯具体批准原文与应用材料；尚未应用的旧候选按 [REVIEW](REVIEW.md#旧待审包与历史记录) 重新准备，不补造版本或继承旧批准。
3. 运行 `resume-cleanup` 检查本机临时批次，再用 `snapshot` 暂存本批目标。清理与恢复按下节生命周期执行。
4. 在共享源之外准备最终内容。按依赖顺序由对应入口应用，正式写入前再次核对附件摘要，每个写入前再次核对目标基线，记录作者预期 SHA-256。
5. 用 `seal --expected` 核对整批实际结果，运行约定检查。必要验证失败时停止批次，恢复属于本批且没有后续变化的内容，并验证恢复结果。
6. README 使用现有生成器预览及更新；记忆维护日期、必要来源和 CHANGELOG 后运行 lint；脚本运行有关测试。
7. 按 [决定记录与应用回执接口](EVIDENCE.md#决定记录与应用回执接口) 保存绑定具体候选版本的精简应用回执（含 proposal_digests 与作者摘要）、实际验证与待验边界；用统一查询复核本批版本、回执可读性、目标摘要及实际验证环境，再调用 `finish` 自动清理本批临时旧内容。清理完成才作为批次收尾；回执记录清理后本工具不再提供该批旧内容恢复。

## 临时副本生命周期

恢复能力只覆盖本批修改与约定验证期间。副本只包含本批目标，不复制整个体系。临时目录仅由本机工具创建；正常验证通过，或成功回退并验证恢复后，`finish` 核对源摘要、验证材料和目录归属，自动删除该批临时目录。精简回执保留摘要和状态，不保留旧内容。

验证记录必须位于待清理目录之外，含至少一项实际检查。每项给出名称、真实退出码、原输出文件和该文件 SHA-256；全部退出码为零且原输出未变，才允许结束。工具核对材料完整性，治理 Agent 负责检查覆盖与结果真实性。不能用模型自己的“有效”判断代替检查。

中断后，下次维护先运行 `resume-cleanup`；`snapshot` 也会自动检查同目录。已经验证、已有完整回执但清理中断的批次继续清理。未完成批次先报告阶段并暂停新增副本，避免积累：

- 未写入：核对原基线，登记未变摘要并检查后结束。
- 已部分写入：依据预先保存的作者预期登记实际属于本批的写入，恢复并验证后结束。
- 源文件、验证材料或临时目录有外部变化：停止覆盖和清理，说明路径、大小与所需处理；保持既有批准范围，只有新增动作才重新审批。

按状态处理，不按年龄盲删，不安装后台清理或定时任务。清理只操作工具登记的旧内容和清单；存在陌生文件或链接时停止删除。旧格式目录不自动认领，只有明确清理批准、既有完成证据和后续批准变更核对齐备时另行处理。其他设备待验状态留在报告，不无限延长本机副本保留。

```bash
python3 -B scripts/batch_guard.py resume-cleanup --directory <本机临时批次目录>
python3 -B scripts/batch_guard.py snapshot --root <共享根> --targets <目标列表.json> --output <本机批次目录> --approval-ref <实际批准引用>
python3 -B scripts/batch_guard.py check --manifest <本机批次目录/manifest.json>
python3 -B scripts/batch_guard.py seal --manifest <manifest.json> --expected <作者预期摘要.json>
python3 -B scripts/batch_guard.py rollback --manifest <manifest.json>
python3 -B scripts/batch_guard.py finish --manifest <manifest.json> --verification <实际验证.json> --receipt <本机精简回执.json>
```

targets 为相对文件列表，expected 为相对文件到 SHA-256/null 的映射。验证文件结构为 `{"status":"passed","checks":[{"name":"实际检查名称","exit_code":0,"evidence_file":"本机原输出文件","sha256":"实际摘要"}]}`。精简回执及验证原输出位于批次目录之外，路径按本机发现。

恢复前检查全部目标，仅恢复已登记的本批写入。新文件只删除仍等于作者预期的内容；任何后续外部修改均停止自动恢复。工具提供本机冲突检测，不提供 iCloud 分布式锁或跨文件事务。清理后的长期回退需另有已批准版本历史，本工具不假定 iCloud 已提供可靠历史。

## 第三方本地适配

优先沿用该技能已批准的适配入口。不存在时可提出旁挂的本地说明，但必须同时提出读取入口和验证方式；通过共享路由选择目标技能时，在执行前读取该技能 `local/ADAPTATION.md`（若存在），记录实际读取证据。

直接原生加载未经过共享路由的路径须单独验证。失败时标记该环境适配未生效，提出最小的入口适配或包装方案，经过同一变更包审阅后处理；不声称一个旁挂文件对所有宿主自动生效。首版不对全部第三方技能统一创建旁挂文件或改写正文。

上游升级沿用 `agent-shared-skills` 的版本、差异和覆盖核对流程。保留本次获准的调用元数据覆盖；升级时重新比较触发语义，其他差异仍需审阅。

## 阶段记录

源就绪、文件同步、链接正确、Agent 已发现、代表场景执行通过、后续问题减少分别记录，附环境、时间与验证引用。其他设备读取到同一批变更摘要后才能记录其文件同步；历史实例记录不代表当前在线。运行配置建议与共享源改动分开。
