# 与 TencentDB Agent Memory 的选型对比

[English](comparison.en.md) · **简体中文** · [项目首页](../README_CN.md)

TencentDB Agent Memory 是一套功能完整的服务化记忆方案，提供记忆分层处理、管理面板、资产组织、权限及 Agent 接入。它在集中运营、多用户权限和自动处理方面有明确价值；这里比较部署与协作取舍，不给出未经实测的质量排名。

Agent Shared System 选择另一条路径：用可直接阅读的文件维护技能、长期记忆和规则，通过同步工具送到各机本地，再由 Agent 按需读取、提炼和审阅。

## 谁更适合文件共享

- 在办公室 Windows 与家中 Mac 之间接续工作的个人。
- 同时使用多台电脑、独立 Linux 或 WSL、多个 Agent 的使用者。
- 希望共享技能、审阅过的记忆和方法，又希望直接阅读、修改、备份文件的人。
- 已有可靠同步工具、愿意按文件协调写入的个人或小团队。

下班后可以继续读取已同步到家中电脑的背景，不必保持办公室那台电脑作为记忆服务器在线。但新内容何时到达仍取决于同步工具，Agent 的模型或外部工具也可能需要联网。

## 具体区别

| 维度 | Agent Shared System | TencentDB Agent Memory |
|---|---|---|
| 共享方式 | 同步文件到各机副本，本地读取 | 多客户端请求运行中的共同后台 |
| 后台部署 | 核心无需常驻记忆服务或数据库 | 可在本机、WSL 或服务器部署服务；多设备共用需网络可达 |
| 跨地点接续 | 使用所选同步工具，无需另设访问办公室后台的通道 | 需配置到同一后台的网络连接 |
| 多电脑同时使用 | 各机可读取本地文件；同文件并发写需协调 | 写入与访问由后台处理；具体能力依版本与部署验证 |
| 记忆形成 | Agent 整理、来源核验、审阅和授权后维护正式文本 | 后台分层提炼、自动去重及资产处理 |
| 内容审计 | 支持组织多 Agent 独立复核；并非安装后自动审计 | 检查的默认路径以模型加工和事件留痕为主，不等同多 Agent 交叉审核 |
| 检索 | 现行主题、关键词、同义词及来源导航，Agent 负责扩词 | BM25、可选向量检索及相关工具接口 |
| 权限与管理 | 同步工具的文件权限、可读文本；不含精细记忆 ACL | 提供团队、用户、资产可见性及权限管理 |
| 知识与代码 | 核心不自带 Wiki 编译或代码图谱 | 提供 Wiki 与 CodeGraph 资产能力 |
| 运维 | 维护同步、文件组织、本机依赖和审阅流程 | 维护服务、网络、数据库、模型接入、备份及升级 |

## 本项目的优势与边界

两边都可以另外组织多 Agent 审查；本项目提供文件审阅约定，不把它表述为腾讯无法实现的能力。

优势来自适用条件：跨地点读取不依赖一台自建记忆主机在线；文件格式易读、易迁移；不同 Agent 可复用同一方法；规则与技能可审阅后演进；正式记忆与候选证据分开；第三方依赖按机器准备。

多 Agent 复核只有在实际组织执行时才成立。多个模型重复同一证据不会自动提高可靠性，文件可读也不自动证明结论正确。两套系统没有进行同任务准确率、召回率、Token 成本或稳定性对照，因此不宣称本项目整体更先进或效果更好。

需要集中管理、多人细粒度授权、持续自动采集和丰富资产后台时，腾讯方案值得优先评估；需要低基础设施负担的跨端文件协作时，本项目值得尝试。二者可以借鉴或组合，不必全面替换。
